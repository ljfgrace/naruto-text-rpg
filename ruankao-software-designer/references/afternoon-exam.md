# 下午题（应用技术）5 道大题套路

> 下午题是软件设计师真正的决胜场。上午题 45 分容易蒙混，下午题 45 分必须靠套路。

## 试题一：数据流图 DFD（15 分）

### 题型
给一个顶层图（0 层图）和 1 层分解图，让你：
1. 找出缺失的外部实体 / 数据存储 / 数据流
2. 指出某条数据流的起点和终点
3. 加工编号（0、1.1、1.2 这种层级编号）

### 答题套路
1. **平衡原则**：父图与子图的输入输出数据流必须完全一致（数量+方向）
2. **外部实体**：系统边界之外的人/部门/外部系统（用方框表示）
3. **数据存储**：文件/表/数据库（用双横线或开口矩形）
4. **加工**：必须有动词，不能只有名词；不能只有输入没有输出（黑洞），也不能只有输出没有输入（奇迹）
5. **答题时先列所有数据流清单**，再对照父子图找缺失

### 易错
- 外部实体和数据存储混淆
- 忽略"反馈"类数据流
- 编号错（子图编号必须带父加工号，如 1.1、1.2）

## 试题二：数据库设计 E-R（15 分）

### 题型
给 E-R 图（实体 + 属性 + 联系），让你：
1. 把 E-R 图转成关系模式（填主键 PK、外键 FK）
2. 补充缺失的联系/实体
3. 判断范式级别（通常是 3NF）

### 转关系模式规则
- **1:1 联系**：联系可以合并到任意一端，外键放哪边都行
- **1:N 联系**：外键放在 N 端（多的那一方），联系本身**不单独建表**
- **M:N 联系**：**必须单独建表**，主键是两端实体主键的组合
- **多值属性**：单独建表

### 答题模板
```
实体名(主键, 属性1, 属性2, ...)
联系名(实体1主键, 实体2主键, 联系自身属性)
```

### 易错
- M:N 忘了建中间表
- 外键位置放反（1:N 应该放 N 端）
- 多值属性当成普通属性

## 试题三：UML 建模（15 分）

### 题型
给一个场景描述（如"在线考试系统"），给一张不完整的 UML 图，让你：
1. 填类名 / 方法名
2. 填关联的多重度（1、0..1、*、1..*）
3. 判断这是哪种 UML 图（用例图 / 类图 / 顺序图 / 状态图）

### 常见多重度
- `1`：有且仅有一个
- `0..1`：零或一个
- `*` 或 `0..*`：零或多个
- `1..*`：至少一个
- `1..n`：指定数量

### 用例图关键概念
- **包含（<<include>>）**：基用例**一定会**执行被包含用例（必做步骤）
- **扩展（<<extend>>）**：基用例**条件触发**被扩展用例（可选分支）
- **泛化**：子用例继承父用例

### 易错
- include 和 extend 箭头方向搞反
- 多重度写反（A 对 B 是 1，B 对 A 是 *）

## 试题四：算法 C/C++ 代码填空（15 分）

### 题型
给一段 C 代码（约 30-50 行），空 5-6 个，让你填关键语句。

### 高频算法
1. **动态规划**：最长公共子序列 LCS、0-1 背包、矩阵连乘
2. **贪心**：活动选择、找零
3. **分治**：归并排序、快速排序、二分查找
4. **回溯**：N 皇后、子集和
5. **图**：Dijkstra 最短路径、拓扑排序

### 答题策略
1. **先读注释**：注释会告诉你这一块在干什么
2. **看循环边界**：通常空的是循环条件、递归返回、DP 状态转移方程
3. **对照输入输出**：用一个小例子手动走一遍代码
4. 空里通常是 1-3 行，不要写一大段

### 易错
- 数组下标从 0 还是从 1 开始（题目会给）
- DP 初始化（边界值）
- 递归出口条件

## 试题五：设计模式代码填空（15 分）

### 题型
给一段 Java 或 C++ 代码（约 40-60 行），实现某个设计模式，空 5-6 个。

### 必考模式（按频率）
1. **单例模式**：私有构造、静态实例、getInstance()
2. **工厂方法**：抽象产品 + 具体产品 + 抽象工厂 + 具体工厂
3. **策略模式**：Context 持有 Strategy 接口，运行时切换算法
4. **观察者模式**：Subject 维护 Observer 列表，notify 时逐一 update
5. **装饰器模式**：Decorator 实现 Component 接口并持有 Component
6. **适配器模式**：Adapter 包装 Adaptee 实现 Target 接口

### 答题套路
1. 先判断这是哪个模式（看类图注释或代码结构）
2. 回忆该模式的 UML 角色（如策略模式的 Strategy / ConcreteStrategy / Context）
3. 对着角色名填空：接口名、实现类名、方法名

### 易错
- 搞混装饰器和适配器（装饰器是"增强"，适配器是"转换接口"）
- 观察者模式里 observer 列表的遍历和 notify 调用位置
- 单例模式的线程安全（饱汉/饿汉双重检查）

---

## 下午题通用答题技巧

1. **先做会的**：5 道题按顺序做，卡壳超过 5 分钟先跳过
2. **大题不空着**：即使不确定，相关概念写上也有过程分
3. **名词要标准**：写"主键"不写"主要的 key"，写"外键"不写"连接字段"
4. **画图题用铅笔在草稿纸先列一遍**，再誊到答题卡
